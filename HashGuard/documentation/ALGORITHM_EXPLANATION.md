# MD5 Algorithm and its 8086 Implementation

## 1. What MD5 does
MD5 reads a message of any length and produces a 128-bit digest (32 hex characters). A single changed bit in the
message changes about half of the digest bits, which is why it can detect modified files.

## 2. Steps
1. **Padding.** Append byte `80h`, then zero bytes until the length is 56 mod 64, then the original length *in bits* as a
   64-bit little-endian number. The padded message is a whole number of 64-byte blocks.
2. **Initial state** (four 32-bit words): `A=67452301h B=EFCDAB89h C=98BADCFEh D=10325476h`.
3. **For every 64-byte block:** split into sixteen 32-bit little-endian words `M[0..15]`, copy the state, run 64 steps, then
   add the copy back (mod 2³²).
4. **One step** (i = 0…63): `t = f + A + K[i] + M[g]`; then `A=D; D=C; C=B; B = B + rotl(t, s[i])`.
5. **Digest** = A, B, C, D written little-endian.

| Round | Steps | f | g |
|---|---|---|---|
| 1 | 0–15 | `(B and C) or (not B and D)` | `i` |
| 2 | 16–31 | `(D and B) or (not D and C)` | `(5i+1) mod 16` |
| 3 | 32–47 | `B xor C xor D` | `(3i+5) mod 16` |
| 4 | 48–63 | `C xor (B or not D)` | `7i mod 16` |

`K[i] = floor(2³² × |sin(i+1)|)` (64 constants, stored in `md5K` in `MD5.ASM`, generated by program and checked against
the specification). Rotation amounts: round 1 `7,12,17,22`, round 2 `5,9,14,20`, round 3 `4,11,16,23`, round 4 `6,10,15,21`
(each group repeated four times, table `md5S`).

## 3. 32-bit arithmetic on a 16-bit CPU
The 8086 has no 32-bit registers. Every MD5 word is two 16-bit words (low word first in memory, which is little-endian).
In registers a word is held in the pair **DX:AX** (DX high, AX low).

| Operation | 8086 code |
|---|---|
| 32-bit add | `add ax,lo` then `adc dx,hi` (carry flows from low to high) |
| and / or / xor / not | the same instruction on the low halves, then on the high halves |
| rotate left by 1 | `shl ax,1` / `rcl dx,1` / `adc ax,0` (bit 31 wraps to bit 0) |
| rotate left by s | the three instructions above repeated `s` times, counter in `CL` |

The 8086 can only shift by 1 or by `CL`, so there are no `shl ax,4` style instructions anywhere in the project.

## 4. Streaming design (`MD5_Init`, `MD5_Update`, `MD5_Final`)
Files are read 512 bytes at a time. `MD5_Update` copies bytes into a 64-byte buffer `blk`; whenever it fills, `MD5_Transform`
processes it. A 32-bit byte counter (`md5LenLo/Hi`) tracks the length. `MD5_Final` computes the bit length
(`len × 8`, three shift-left steps through `DX:AX:BX`), appends `80h`, pads with zeros (using an extra block when fewer than
9 bytes remain), writes the 64-bit length at bytes 56–63, and runs the last transform. The four state words, already in
little-endian layout in memory, are copied to `md5Digest`.

## 5. Verification
Executed with the interpreter in `verify/`: empty string, `a`, `abc`, `message digest`, `a…z`, the 62-character
alphanumeric string, 80 digits, and padding edge cases (55, 56, 63, 64 zero bytes) and a 2308-byte binary input,
each fed both in 512-byte and 7-byte pieces. All digests equal Python's `hashlib.md5`. The known published values
(RFC 1321) are `d41d8cd98f00b204e9800998ecf8427e` (empty), `0cc175b9c0f1b6a831c399e269772661` (a),
`900150983cd24fb0d6963f7d28e17f72` (abc), `f96b697d7cb7938d525a2f31aaf161d0` (message digest) and
`c3fcd3d76192e4007dfb496cca67e13b` (a–z).
